# Питание и лаборатории

## План питания (`ai_coach/nutrition.py`)

План на неделю строится из **энергобаланса**, а не из «магических 2000 ккал»:

1. **BMR** — Mifflin-St Jeor (вес, рост, возраст).
2. **Тренировки** — ккал с часов/активностей по дням недели.
3. **NEAT** — бытовая активность от средних шагов (~0.00045 ккал/кг/шаг,
   консервативный коэффициент).

Итоговый TDEE распределяется по приёмам пищи с учётом режима (4 «скорости»:
похудение/поддержание/набор + bulk), граммы — в готовом виде, ккал — по
приёмам. Защитные полы: ниже BMR и 1500 ккал не опускаемся. В промпт
стадии 3 планирования питание видит extras дня — «Rest + растяжка» не
считается чистым отдыхом.

## Дневник еды (`ai_coach/meal_log.py`)

Атлет пишет «съел тарелку каши и два яйца» → один AI-вызов дешёвой моделью
→ строгий JSON: позиции, граммы, ккал/БЖУ, слот приёма (завтрак/обед/ужин/
перекусы/до-во время-после тренировки).

Ключевые решения:

- **Fail-fast вместо молчаливой ерунды.** Неоднозначная порция
  («порция пасты в кафе») → `need_clarify=true` и короткий вопрос
  с вариантами («Сколько примерно? ~200 г / ~350 г») — запись **не**
  создаётся, атлету переспрашивают. Невалидный ответ модели — тоже.
- **Постоянство важнее точности.** Оценка честно объявляется ±10–15% при
  указанных граммах; ккал округляются до 5 — метод оценивает день к дню
  одинаково, и бот не притворяется точным.
- **Остаток нормы**: разбор дня показывает план vs съедено по слотам —
  «до тренировки осталось ~40 г углеводов».

## Лаборатории (`ai_coach/labs.py`)

Анализы крови и газоанализ (CPET) — пайплайн «PDF/фото → разбор → зона»:

1. **Извлечение**: текстовый слой PDF (pdftotext) или vision-модель для
   фото/сканов → нормализованный JSON.
2. **Подтверждение человеком**: атлет видит разобранные значения и
   подтверждает — только потом данные сохраняются (`coach.lab_tests`).
   Исходные файлы **не хранятся** (медданные) — только извлечённый JSON.
3. **Rule-флаги крови**: референсные пороги бегуна с уровнями
   warn/alarm — ферритин, гемоглобин, витамин D, ТТГ, СРБ, АЛТ/АСТ.
   Например: ферритин 20–30 → «запас железа на нижней границе — типичная
   скрытая причина падения темпов».
4. **Зоны из CPET**: вентиляционные пороги маппятся в 7 зон ICU
   (VT1 → низ Z3, VT2 → низ Z5, `zones_source='lab_test'`) — лаборатория
   становится ещё одним источником правды о зонах наравне с ICU и
   полевым тестом.
5. **AI-разбор с динамикой**: сравнение с предыдущими анализами, рекомендации
   какие лаборатории пересдать (дедупликация подсказок 14 дней).

**Бот не ставит диагнозов**: каждый разбор завершается дисклеймером
«разбор не является медицинским диагнозом — отклонения обсуждай с врачом».

## Пульсовые зоны (`ai_coach/zones.py`)

Единый модуль: загрузка/синк зон из ICU, оценка по макс. пульсу
(`estimate_zones_from_max_hr`), форматирование. Зоны — **источник истины**
для всех AI-промптов: планирование, чат, разбор тренировки обязаны брать
таргеты только из зон-контекста, не «выдумывать» свои.

## Смежное

- **Тест макс. пульса** (`ai_coach/vdot.py`): 3 км или тест Купера →
  прогнозы по формуле Ригеля + max HR = пульс теста + 5 → зоны.
- **Best efforts** (`ai_coach/best_efforts.py`): скользящее окно по
  GPS-потокам ICU без AI — 100 м / 1 км / 5 км / 10 км / полумарафон /
  марафон.
- **Оценка атлета** (worker): после ≥2 пробежек модель оценивает уровень,
  реалистичность цели и ETA — переоценка каждые +10 пробежек.
