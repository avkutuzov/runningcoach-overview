# Карточки для соцсетей

## Что умеет

- **Карточка тренировки** (`stats_card.py`, PNG 1080×1350) — премиум
  share-карточка: AI-фон на весь экран, тёмный градиент для текста,
  адаптация под тип активности (бег, вело, бассейн, ходьба, силовая).
- **Карточка недельного прогресса** (`progress_card.py`, PNG 1080×1920,
  сторис-формат) — объём недели → бары за 8 недель → дельты → рекомендации
  тренера → история успеха. Минималистичный дизайн «уровня Strava».
- Обе — чистый PIL (Pillow), без новых зависимостей: шрифты, палитра,
  отрисовка градиентов и панелей — всё своё.

## AI-фоны (`card_bg.py`)

Фон карточки генерирует image-модель (Gemini через единый AI-шлюз).
Промпт собирается из условий:

```python
scene = pick_template(start_hour, variety)          # сцена по времени суток
clauses = [scene, _weather_clause(weather),          # погода снаружи
           _season_clause(month), _REALISM]          # сезон, реализм
if subject_photos: clauses.append(_SUBJECT_CLAUSE)   # герои в сцене
prompt = ", ".join(filter(None, clauses))
```

Сцены подобраны по времени суток (утро/день/вечер/ночь), сезон — по месяцу,
погода вставляется текстом («лёгкий дождь», «снег»). Для атлетов из крупных
городов — пейзажные шаблоны с достопримечательностями, ротация по variety.

## Кэш и ключ (`card_bg.py`)

Каждая генерация — деньги и секунды. Поэтому:

```python
photos_key = hashlib.sha1(
    b"".join(sorted(hashlib.sha1(p).digest() for p in subject_photos))
).hexdigest()[:12]                                   # хеш НАБОРА фото
key = hashlib.sha1(f"{IMAGE_MODEL}|{prompt}|{photos_key}".encode()).hexdigest()[:16]
cache_file = CACHE_DIR / f"{key}.png"
```

Ключ = **модель + полный промпт + хеш фото героя**. Одинаковый запрос —
мгновенный ответ из кэша; промах — генерация и атомарная запись.

Детали, которые обычно забывают:

- **Лок на ключ кэша**: Telegram и VK могут запросить одну карточку
  одновременно — вторая платформа ждёт лок и берёт готовый фон, двойной
  генерации не будет.
- **Атомарная запись** (tmp + rename) — частично записанный PNG никогда
  не попадёт в кэш.
- **`bump_variety(athlete_id)`** — счётчик разнообразия под локом, общий
  для обоих ботов одного атлета: каждое нажатие `/card` берёт **следующую**
  сцену (`variety % len(сцен)`), а не кэш-клон. Без него кэш честно отдавал
  бы одну и ту же картинку.
- Фото-референсы (герой/питомец) в ключ входят **отсортированным набором**
  хешей — порядок файлов не влияет на ключ.

## Окно из 5 фото атлета

Функции `list/add/clear_subject_photos` ведут скользящее окно из 5 фото
на атлета: команда `/myphoto` добавляет снимки, `/myphoto off` чистит,
батч из нескольких фото = одно подтверждение (debounce 10 с). Модель
встраивает героя в сцену по референсам; фото лежат вне БД, в файловом
хранилище по атлетам.

## Инженерные решения

- **Никаких внешних библиотек рендера**: PIL + системные шрифты Ubuntu —
  карточка собирается за миллисекунды, AI тратится только на фон.
- **Прогресс-карточка переиспользует дизайн-слой** тренировочной (палитра,
  шрифты, `_make_bg` импортируются из `stats_card.py`) — единый визуальный
  язык.
- **Промоконтакт**: кэш на диске переживает рестарты, ключи — детерминированы,
  поэтому эффект «одна и та же сцена за все нажатия» ловится и правится
  одним изменением формулы ключа.
- Кэш-ключ включает **модель** — смена image-модели не коллизирует со
  старым кэшем.
