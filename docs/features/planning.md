# Планирование тренировок

## Что умеет

- План недели с этапами, зонами, темпами, СБУ, силовыми и растяжкой.
- Учёт пульсовых зон (из ICU / анкеты / полевого теста), формы (CTL/ATL/TSB),
  болей, энергобаланса, целей и погоды.
- Изменение тренировок диалогом: «убери интервалы в среду, переставь лонг
  на воскресенье» — с одобрением атлетом.
- Элитный режим: несколько беговых сессий в день, объём по медиане факта.

## Трёхстадийная генерация (`ai_coach/planner.py`)

1. **Стадия 1 — тренировки.** Сильная модель получает контекст: зоны,
   2 недели нагрузки, боли, энергобаланс, цели, результаты тестов →
   план недели в JSON.
2. **Стадия 2 — DSL для часов.** Дешёвая модель конвертирует каждый день
   в DSL-этапы (разминка/основной/заминка с таргетами зоны и темпа) —
   формат, который потом уходит в календарь intervals.icu и на часы.
3. **Стадия 3 — питание.** Дешёвая модель строит план питания по нагрузке
   дня (важно: extras `<day>_stretch/_indoor` попадают в «нагрузку по дням» —
   день «Rest + растяжка» не считается чистым отдыхом).

## Элитный планер (`ai_coach/elite_planner.py`)

Для атлетов с большими объёмами (маркер `'_mode': 'elite'` в корне плана):

- В день 1–3 **беговых слота** (`monday`, `monday_2`, `monday_3`) — порции
  по медианной длине сессий атлета, объём набирается суммой сессий.
- Правила любителя (качество ≤ 8–10 км/нед, день после лонга = Rest)
  **не применяются**.
- План строится из **полного факта** (400 дней) через агрегаты профиля,
  а не из последних 14 дней.
- Утренний совет показывает раскладку по слотам, а не только основную
  сессию.

## Инварианты плана

Ядро надёжности — спецификация «контракта генерации» (родилась из разбора
поломок «план ломается каждую неделю новым способом»): это не пять разных
багов, а повторяющиеся **классы** нарушений контракта. Выдержка реестра
(полный — 17 инвариантов):

| Инвариант | Гарант |
|---|---|
| `distance_km` дня = сумма ВСЕХ дистанционных шагов DSL (иначе название события в ICU не совпадёт с этапами на часах) | код: `plan_push.reconcile_day_distances` |
| Locked-extras (комплексы растяжки/силовой, зафиксированные атлетом) при пересчёте не теряются; выдуманные — удаляются | код: planner, обе ветви |
| Никаких `[:N]`-обрезок на передаче контента (молчаливая порча: модель видела 8 строк комплекса из 26 и честно пересобрала только их) | ревью + смоуки |
| Каждый день в AI-промпте — с датой и меткой «сегодня атлета» | код во всех конструкторах промптов |
| DSL-синтаксис: `1.5km`, минуты ≥ 100 → `Nmtr`, зоны только с суффиксом | код: `plan_push.sanitize_icu_workout` |
| Диалог НЕ перезаписывает план сам: только после «✅» атлета | код-гейт воркера |
| Два плана (текущая + следующая неделя) — выбор по смыслу операции (`get_current_plan` / `get_upcoming_plan`), никогда «последний активный» | ревью каждого нового места |

Анти-паттерны из того же разбора:

- **«Конвенция только в промпте»** — правило держится текстом, модель
  нарушает, никто не проверяет. Решение: инвариант держит код на выходе
  пайплайна; промпт — вторая линия.
- **Мутирующий парсер общих данных** — `parse_plan` с `pop()` ронял второй
  форматтер. Решение: чистые функции для общих данных.
- **Непротестированный шов сервисов** — смоук участника в изоляции зелёный,
  протокол бот↔воркер сломан. Решение: смоук обеих сторон каждого шва.

## Approve-механика изменений (`pending_actions`)

Требование к продукту: тренер **сначала предлагает** план изменений и
спрашивает разрешение — применяет только после «да».

- Модель отвечает конкретным планом изменений и заканчивает маркером
  `[PROPOSE:<action> k=v ...]`.
- Код-гейт воркера: `[PROPOSE]` (и проскочивший `[ACTION]` — страховка)
  **никогда** не применяется напрямую — сохраняется заявка
  `coach.pending_actions` (одна на чат, TTL 12 часов), под ответом —
  inline-кнопки «✅ Применить» / «✖️ Отмена».
- «✅» → задача `pending_apply` → воркер (и только воркер) диспетчит
  действие с накопленными пожеланиями диалога.
- Несколько `[PROPOSE]` в одном ответе = одна заявка-цепочка, применяется
  по порядку — договорённости не теряются.
- Честное обновление ICU в «сегодня»: если пробежка уже выполнена,
  беговое событие — история (не трогаем), но extras (растяжка/силовая)
  обновляются по совпадению имени и расхождению DSL.

Инвариант формулируется так: **диалог в одиночку не может перезаписать
план**. Промпт — первая линия (красивый текст предложения), кнопка — вторая.

## Правила атлета и honest limits

- `ai_coach/rules.py` — постоянные правила («прокатку бицепса бедра
  выкидывай») инжектятся во все промпты с лимитами.
- Конфликты модели («⚠️ Учтено с ограничениями») и механические правки кода
  («🔧 Техническая поправка») рендерятся **разными блоками** — атлет всегда
  видит, кто и почему что-то изменил.
- Замена типа бегового дня («убери плавание») — не AI, а код-экшен
  `change_day`: тип = Rest, дистанция и DSL очищены, extras дня сохранены,
  питание перестраивается. Детерминированное — не через модель.
