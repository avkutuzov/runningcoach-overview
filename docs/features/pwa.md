# PWA и веб-вход

## Что умеет

- **PWA-мини-приложение**: план на сегодня и на неделю, лента сообщений,
  чат с тренером — в браузере и «на рабочий стол» телефона
  (manifest + service-ассеты).
- **OAuth intervals.icu** — вход без пароля и без ручного ввода athlete ID.
- **Мини-приложение входа из ботов** (`/auth/bot`) — главное звено,
  связывающее бота и веб.

## API (`api_server/main.py`)

FastAPI-приложение, запускается на локальном порту за nginx (наружу —
только проксированные `/api` и `/auth`). Эндпоинты:

| Группа | Эндпоинты |
|---|---|
| План | `GET /api/plan/today`, `GET /api/plan/week` |
| Чат | `GET /api/messages`, `POST /api/chat`, `POST /api/chat/regen` |
| Вход ботов | `POST /api/bot/link/prepare` |
| OAuth | `GET /auth/login`, `GET /auth/callback`, `GET /auth/logout`, `GET /auth/status` |
| Мини-приложение | `GET /auth/bot` (Telegram), `GET /auth/vk` (VK) |

## OAuth-флоу из ботов

Функционально самое интересное: связка «мессенджер ↔ веб ↔ ICU».

1. Атлет в боте нажимает **«🔑 Войти через intervals.icu»** → открывается
   мини-приложение (Telegram `web_app` / VK `open_app`).
2. Веб проверяет подписанные `initData` (TG) / `vkParams` (VK) —
   личность подтверждена мессенджером, пароля нет.
3. `POST /api/bot/link/prepare` кладёт **одноразовый state** в
   `coach.oauth_pending` (TTL 2 часа) и редиректит на OAuth ICU.
4. ICU возвращает код → `GET /auth/callback` обменивает его на токен,
   находит pending-state и вызывает связку аккаунтов.
5. Связка (`_link_bot_user`): гость → полноценный аккаунт, смена
   ICU-аккаунта → перенос данных на новый athlete ID по всем таблицам;
   занятость ICU-id проверяется заранее с понятной ошибкой.
6. Страница-результат **закрывается сама** (~2,5 с), бот в чате присылает
   подтверждение и вопрос «⌚ Привязать часы?» с кнопкой на настройки
   подключений ICU (только аккаунтам без активностей — тем, у кого
   активности есть, вопрос не задаётся).

Фолбэк: если домен не привязан в настройках бота (или не задан VK_APP_ID),
кнопка становится URL-кнопкой — флоу не ломается.

## Задача как канал

Чат PWA — полноценный канал, а не «витрина»: сообщение из веба ставит
задачу в ту же очередь `job_queue` с каналом `web`, воркер отвечает
записью в ленту `coach.messages`. Никакой отдельной логики «для сайта».

## Безопасность

- Секреты — только в env-файле вне репозитория; OAuth client-id/secret,
  токены ботов и ключи AI не попадают ни в код, ни в логи.
- Session-токены PWA хранятся в БД (`app_users`), выход — `GET /auth/logout`.
- OAuth-state одноразовый и с TTL — повторное использование ссылки входа
  и «висящие» заявки невозможны.
- nginx наружу отдаёт только `/api` и `/auth` — само приложение не
  опубликовано напрямую.
